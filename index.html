E—01Integrity

Crunch &
Bubbles

Restaurant POS & analytics platform
What it proves — Real money moves through this. The guarantees live in the database, not in a hope that the app layer behaves.

A production-grade dine-in point of sale, built from an empty schema. I treated it as a data-integrity problem first and a UI second: if the numbers can't be trusted, the dashboard on top is decoration.

Live portal ↗ Source ↗ Sign-in required
SchemaNormalized MySQL. Bills and Payments decoupled, so one bill settles across cash + UPI natively and refunds are first-class rows. ON DELETE RESTRICT keeps financial history from being orphaned.
TransactionsStored procedures wrap order placement and stock depletion in explicit COMMIT / ROLLBACK blocks. A half-written order can't exist.
AuditTriggers capture row state as JSON snapshots into an immutable AuditLog — the difference between suspecting tampering and proving it.
AnalyticsWindow functions (RANK, LAG) surface peak hours and per-staff performance directly in SQL.
MySQLNode.jsExpressReact 19Recharts
E—02Privacy

Cipher
Self

Personal privacy intelligence
What it proves — You can tell someone they've been breached without ever receiving the thing that identifies them.

A privacy exposure tool built for Vibexathon 1.0. It checks an address against known breach corpora, scores the result, then does something more useful than a red banner: it shows what the exposure is worth to someone buying it.

Live site ↗ Try demo@cipherself.in
LookupBreach detection via the XposedOrNot API using a k-anonymity range query — only a hash prefix leaves the client, so the full identifier is never transmitted or stored.
ScoringA composite DNA Score (0–100) weighing breach count, recency and the sensitivity of leaked field classes, so a leaked password and a newsletter signup don't count the same.
FramingDark-web valuation in ₹ — abstract risk translated into a number people actually react to.
SimulationAn adversary walkthrough narrating how an attacker would chain the specific exposures found, turning a report into a threat model.
ReactViteNode.jsXposedOrNotGroq
E—03Secrets

Code
Beta

AI-assisted coding curriculum
What it proves — The credential stays on the server. The obvious version of this app ships a paid API key to every visitor's browser; this one doesn't.

A gamified learning platform with XP progression, graded challenges and a tutor that answers in context. The interesting engineering isn't the lessons — it's the boundary between the browser and the model.

Live site ↗ Source ↗
BoundaryAll model calls route through a Node.js proxy. The client posts a question to my endpoint; the key, the provider and the prompt scaffolding never leave the server.
TutorGroq-hosted inference for low-latency answers, scoped to the lesson the learner is on rather than answering anything asked of it.
ProgressionXP-based advancement across challenges and languages, with state that survives a refresh.
JavaScriptNode.jsGroq APIVercel
E—04Craft

This
Site

Hand-built, no framework
What it proves — Restraint. One HTML file, no framework, no build step, no tracking.

Every animation here is native: sticky stacks are CSS, the liquid word is an SVG filter, reveals are IntersectionObserver. No GSAP, no Lenis, no 120KB of scroll library — because the platform already does this.

Live site ↗ Source ↗
DependenciesZero. Even the fonts are self-hosted, so opening this page makes no third-party request at all. No analytics, no cookie banner to decline.
AccessSemantic landmarks, keyboard-operable menu, visible focus rings, full prefers-reduced-motion support.
MotionGoo via feGaussianBlur + feColorMatrix; card stack via position:sticky and one rAF loop.
HTMLCSSVanilla JSSVG Filters
